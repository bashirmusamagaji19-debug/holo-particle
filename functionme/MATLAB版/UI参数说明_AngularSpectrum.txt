对应文件：

==================================================
二、左侧参数区详解
==================================================

1. `z最小值 (mm)`
含义：z 扫描起点。  
影响：决定重建的最近深度；设得过大时，近处粒子会被排除在扫描范围外。

2. `z最大值 (mm)`
含义：z 扫描终点。  
影响：决定重建的最远深度；设得过小时，远处粒子无法进入结果。

3. `z步长 (um)`
含义：z 方向采样间隔。  
影响：
- 越小，z 定位更细，但计算更慢
- 越大，计算更快，但 z 定位更粗

4. `波长 (nm)`
含义：重建使用的激光波长。  
影响：直接进入传播相位计算；填错会导致焦面位置和重建尺度偏移。

5. `像元尺寸 (um)`
含义：相机单像元物理尺寸。  
影响：
- 传播频率坐标计算
- 粒径从像素转换到微米
- 统计结果中的空间尺度换算

6. `重建方法`
含义：在两条主链路之间切换。

当前实际对应关系：
- 方法1：GUI 主路径实际调用 `Fresnel_reconstructFastStats`
- 方法2：调用 `AS_reconstructCS`

区别：
- 方法1：直接产出统计摘要，不保留完整 3D 体
- 方法2：先生成完整 3D 体，再做定位和统计

7. `填充大小`
含义：方法2中对输入图像做零填充的边宽。  
影响：
- 只影响 `AS_reconstructCS`
- 对方法1快速统计无直接作用

8. `tau`
含义：TwIST 正则化强度。  
影响：
- 越大，解更稀疏
- 过大可能漏粒子
- 过小可能噪声较多

9. `TV迭代数`
含义：方法2里 TV 收缩相关的内层迭代次数。  
影响：越大通常越平滑，但计算更慢。

10. `容差`
含义：TwIST 收敛判据。  
影响：越小越严格，耗时通常越长。

11. `迭代次数`
含义：TwIST 最大迭代次数。  
影响：越大越可能收敛得更充分，但时间更长。

12. `Use GPU acceleration`
含义：是否尝试 GPU。  
影响：
- 方法1、方法2都支持尝试 GPU
- 不可用时会自动回退到 CPU 或混合模式

==================================================
三、右侧统计参数区详解
==================================================

1. `峰值比阈值`
含义：轴向峰值显著性阈值。  
在方法2里，常见形式是：
`peakRatio = max(axialCurve) / mean(axialCurve)`

作用：
- 越大，过滤越严格
- 越小，保留更多候选，也更容易带入噪声

建议：
- 误检偏多时，向上调
- 漏检明显时，向下调

2. `Z边界层数`
含义：要求峰值不要落在 z 扫描边界附近的缓冲层数。  
作用：
- 过滤“峰值贴边”的不稳定结果
- 数值越大，过滤越严格

3. `二维识别阈值`
这是当前最容易误解的参数。

在方法1里：
- 它作用在归一化后的 `mip2D`
- 先执行 `AS_normalizeImage(mip2D)`
- 再用该阈值做二值化

在方法2里：
- 它作用在原始 `mip2D`
- 实际阈值是 `xyThreshold * max(mip2D(:))`

这意味着：
- 同一个阈值，方法1和方法2的实际效果并不完全等价

当前 GUI 文本框默认值是 `0.75`。  
另一个实现细节是：如果运行时读取失败，内部 fallback 仍会回退到 `0.85`。用户调参时应以界面显示值为准。

4. `ROI半径倍率`
含义：自适应搜索 ROI 的初始半径提示量。  
它不是最终粒径，也不是最终测量窗口大小。

当前作用位置：
- 方法1：传入 `Fresnel_reconstructFastStats`
- 方法2：传入 `AS_localizeParticles3D`

当前影响方式：
- 先参与构造搜索 ROI
- 再结合候选框大小、最小物理半径、边缘能量扩张规则，得到最终搜索 ROI

规律：
- 值越大，搜索 ROI 初始更宽，抗偏移更强，但更容易混入邻近粒子或背景
- 值越小，搜索更聚焦，但对中心偏差更敏感

5. `ROI最小半径`
含义：搜索 ROI 的像素级下限，单位 px。  
作用：
- 防止 ROI 过小导致轴向曲线或测量不稳定

需要注意：
- 这个参数主要约束“搜索 ROI”
- 真正用于粒径测量的“测量 ROI”还会在 `AS_refineMeasurementROI` 中继续收缩
- `AS_refineMeasurementROI` 自己的最小测量半径默认是更小的值，不等于这里的 15 px

==================================================
四、参数之间的联动关系
==================================================

当前代码下，最常见的联动关系如下：

1. `z步长` + `z最小值/最大值`
决定 z 采样范围和精度，也决定计算量。

2. `二维识别阈值` + `峰值比阈值` + `Z边界层数`
共同决定“候选粒子能不能最终成为有效粒子”。

3. `ROI半径倍率` + `ROI最小半径`
共同影响搜索 ROI 的初始大小，但最终 ROI 还会再受自适应放大和测量细化影响。

4. `像元尺寸`
直接影响粒径从 px 到 um 的换算；粒径统计解释必须建立在正确像元尺寸上。

5. `重建方法`
会改变整条链路，因此同一组统计参数在两条方法上的效果不一定相同。

==================================================
五、当前代码下需要特别知道的实现细节
==================================================

1. 主重建路径当前没有提供预处理滤波参数。
2. `AS_preprocessHologram` 已经简化为“减背景后做全幅 `max(image)-image` 映射 / 原图做同样映射”。
3. 但 `onReconstruct` 主路径现在实际上直接使用 `dataImg`，没有调用 `AS_preprocessHologram`。
4. 方法1当前会额外做“粒径 22~36 px + 圆度 > 0.6”的启发式筛选。
5. 方法2当前不会做这一步，而是更直接依赖原始 MIP 阈值和轴向判别。
6. 嵌入式 3D 体渲染逻辑还在代码里，但当前界面没有完整暴露成稳定主流程；用户真正能直接看到的核心结果是统计区和弹出的粒子总览窗口。

==================================================
六、按当前代码建议的起始调参思路
==================================================

如果先追求“能稳定出结果”，可从下面这组思路开始：

1. `z最小值 / z最大值`
先确保把样品可能出现的深度范围完整覆盖。

2. `z步长`
先用中等步长；若 z 定位跳动明显，再减小。

3. `二维识别阈值`
当前 GUI 默认 `0.75` 是比较中间的起点：
- 候选太多、噪声明显时调高
- 候选太少、漏检时调低

4. `峰值比阈值`
默认 `1.15` 可作为第一轮筛选起点：
- 假阳性多时上调
- 漏掉真实粒子时下调

5. `ROI半径倍率`
默认 `0.50` 通常够稳；粒子很密集时可以略减，粒子较散或信噪比较差时可以略增。

6. `ROI最小半径`
默认 `15 px` 是当前代码比较保守的搜索下限，不建议一开始就调得很小。
